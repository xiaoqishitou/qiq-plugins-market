# 上架指南

把一个 qiq 插件放进这个市场，一共三步：**写插件 → 打包上架 → 让用户装上**。

---

## 一、写插件

qiq 插件 = 一个引用 `Qiq.Plugin.Sdk` 的 .NET 8 类库，实现 `IPlugin`。

```csharp
using Qiq.Plugin.Sdk;

[QiqPlugin(
    id: "my-plugin",
    name: "我的插件",
    version: "1.0.0",
    Author = "你的名字",
    Description = "一句话说清它是干什么的",
    Permissions = PluginPermission.EventRead | PluginPermission.MessageSend)]
public sealed class MyPlugin : IPlugin
{
    private IPluginContext _ctx = null!;

    public Task OnLoadAsync(IPluginContext context)
    {
        _ctx = context;
        context.Events.MessageReceived += (_, e) => _ctx.Log.Info("hello");
        return Task.CompletedTask;
    }

    public Task OnUnloadAsync() => Task.CompletedTask;
}
```

完整 API（事件、发消息、群管理、存储、定时任务、配置表单）见框架仓库里的
`插件示例和qq所有函数例子/插件开发指南.md`，以及可直接编译的 `GreeterPlugin` 示例。

编译：

```bash
dotnet build -c Release
# 产物：bin/Release/net8.0/MyPlugin.dll
```

> Id 用**小写字母、数字、点、短横线**。它会变成用户的 `plugins/<id>/` 目录名，
> 也是升级时识别"同一个插件"的依据，别随意改。

## 二、打包上架

### 单文件（推荐）

```bash
node tools/publish-plugin.mjs ..\MyPlugin\bin\Release\net8.0\MyPlugin.dll \
  --id my-plugin \
  --name "我的插件" \
  --version 1.0.0 \
  --author 你的名字 \
  --desc "一句话介绍" \
  --tags 工具,娱乐 \
  --category 工具 \
  --license MIT \
  --min-app 0.1.0
```

### 目录（插件带资源文件、语言包、原生库时）

```bash
node tools/publish-plugin.mjs ..\MyPlugin\publish --id my-plugin --name "我的插件" --version 1.0.0
```

目录模式下，如果里面有 `plugin.json`，工具会直接读它的 `id / name / version / author / description / entry`，
只有命令行显式传了的参数才会覆盖。

### 工具做了什么

| 步骤 | 说明 |
|---|---|
| 打包 | 生成 `plugins/<id>-<version>.zip`。单 dll 时会补一份 `plugin.json`（含 id / name / version / author / description / entry / tags / requires / minSdkVersion），框架靠它拿到稳定 Id |
| 校验 | 计算 sha256 与字节数，写进清单，qiq 下载后会核对 |
| 登记 | 写 `market.json`：同 Id 覆盖、新 Id 追加，按 Id 排序 |

想先看看结果：加 `--dry-run`。

### 上线到别的地址

默认写的是相对路径 `plugins/xxx.zip`。要让清单里是绝对地址（比如把市场托管到内网服务器）：

```bash
node tools/publish-plugin.mjs MyPlugin.dll --id my-plugin --version 1.0.0 \
  --base http://192.168.1.10:8320
```

---

## 三、让用户装上

用户侧只需要一个地址：

```
http://<你的机器>:8320/market.json
```

填进 qiq 桌面端「插件 → 市场 → 市场地址」，刷新即可看到并安装。

---

## 发新版本

改完代码重新编译，用同样的 `--id`、新 `--version` 再跑一次上架：

```bash
node tools/publish-plugin.mjs ..\MyPlugin\bin\Release\net8.0\MyPlugin.dll \
  --id my-plugin --name "我的插件" --version 1.1.0 --author 你的名字 --desc "..."
```

清单里该插件的条目会被替换成 1.1.0，下载地址指向新的 zip。
旧的 zip 文件不会被自动删除 —— 想留历史版本可以留着，用户也能手动下载。

---

## 检查清单

上架前过一遍：

- [ ] `--id` 稳定、全小写、不与现有插件重名（`market.json` 里搜一下）
- [ ] `--version` 是有效的三段式版本号
- [ ] `--desc` 一句话说清用途，别写"功能强大"这类空话
- [ ] `--tags` 控制在 1 到 3 个，用户靠它筛
- [ ] 插件只申请真正用到的权限（`Permissions`），用户会看到
- [ ] 依赖了别的插件就写 `--requires other-plugin`
- [ ] 上架后在市场页面点开自己的卡片，确认描述、体积、sha256 都对
- [ ] 至少在本机 qiq 上完整装一次、用一遍
